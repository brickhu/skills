## 一句话介绍

`db-ops` 是一个给 AI 助手用的**技能包**（skill）。装上它，你的 AI 编程助手（Claude Code、Cursor、Zed 等）就拥有了直接操作数据库的能力：

- 你跟它说：**"看看 users 表长什么样"**——它帮你查表结构
- 你说：**"把最近 10 条订单拉出来看看"**——它帮你查数据
- 你说：**"把 id=5 的订单改成已发货，先给我看计划"**——它帮你改数据
- 你说：**"生成一个邀请码"**——它自动完成"生成→入库→查回验证"整套流程

不用记 SQL，不用开数据库工具，像聊天一样就把活干了。

## 数据安全怎么办？这是重点

一听到"让 AI 动数据库"，很多人第一反应是：**它会不会把我库删了？**

这正是 db-ops 最花心思的地方，它的安全设计是"层层设卡"：

**1. 只连你登记过的库（白名单）**
AI 不会自己到处扫环境变量、扫端口、乱连数据库。你登记了哪几个连接，它就只能碰哪几个。白名单外的连接，一律拒绝。

**2. 每次操作先确认连哪个库**
哪怕你只登记了一个库，它执行前也会跟你确认一次："我要连的是这个库，对吗？"——杜绝"以为连的是测试库，实际操作的是生产库"这种事故。

**3. 删改数据要"对暗号"**
UPDATE、DELETE、DROP 这类危险操作，AI 会先给你看一份**计划**（改哪张表、条件是什么、大概影响多少行，它会先跑一遍 count 数给你看），然后让你**手打一串动态口令**才能执行，比如：

```
confirm-DELETE-LOCAL-4
```

注意，口令里带着**连接名和行数**——你不看计划根本答不上来。这招直接防住两件事：手滑误触，和 AI 自作主张替你"确认"。

**4. 全程留日志**
每一次操作都记在审计日志里：什么时候、连的哪个库、干了什么、影响了几行。出了事能追溯。

**5. 密码永不露脸**
连接串在屏幕上永远显示成 `postgres://user:***@host`，密钥自动打码，配置文件权限锁死。想泄露都难。

一句话总结：**AI 负责干活，安全闸门全在你自己手里。**

## 怎么装？两条命令的事

```sh
# 方式一：通过 skills.sh 一键安装
npx skills add brickhu/skills

# 方式二：手动复制（任何支持 SKILL.md 的 AI 助手都行）
mkdir -p ~/.claude/skills
cp -r db-ops ~/.claude/skills/db-ops
```

装完重启一次 AI 会话，它就能自动识别这个技能。

## 怎么配？一个文件 + 一个文件

**第一步，登记连接**：在项目里建一个 `.dbops/` 目录，里面放 `.env` 文件，一行一个数据库连接：

```bash
# .dbops/.env
LOCAL=postgres://user:devpass@localhost:5432/dbname
REMOTE=postgres://user:pass@xxx.proxy.rlwy.net:50930/railway
```

支持 PostgreSQL、MySQL、SQLite，AI 会自动识别类型。

**第二步（可选），打包常用操作**：把"生成邀请码"这类多步流程，写进 `recipes.json`：

```json
{
  "recipes": [
    {
      "name": "添加邀请码",
      "triggers": ["添加邀请码", "生成邀请码"],
      "connection": "LOCAL",
      "prompt": "用 pnpm invites:create <code> 生成邀请码，生成后用 SQL 查回确认已入库"
    }
  ]
}
```

以后你只要说一句"添加邀请码"，AI 就把整套流程跑完。
