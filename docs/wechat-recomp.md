## 现在的设计组件库，为什么你都用不上？

不是它们不好——shadcn/ui、Radix、MUI、Ant Design，一个比一个精致。问题出在"用得上"这三个字上。

深夜 23:47，你在 shadcn/ui 翻到一个 Command Palette，完美契合需求。光标已经悬在复制键上——然后你想起上次的教训：

```text
✗ SyntaxError: JSX expressions must have one parent element   ← 框架不对
✗ [plugin:vite:vue] Unexpected token '<'                       ← 还是框架不对
✗ Unknown utility class: group-hover/…                         ← 样式方案也不对
```

三个报错，来自三个晚上的三个项目。用不上的原因，数来数去就三条：

- **框架对不上**：JSX、hooks、受控组件，复制过来直接报错——最精致的组件库几乎全是 React 写的，而你用的是 SolidJS / Vue / Svelte
- **样式对不上**：组件库用 Tailwind 写的，你的项目用的是 StyleX / CSS-in-JS，class 满天飞，接不进来
- **设计对不上**：组件库自带一套 design token，跟你的设计系统打架，改起来比重写还累

于是你合上页面，安慰自己"回头自己写一个"——然后就没有然后了。**看中 → 复制 → 报错 → 放弃 → 手搓轮子**，这就是很多非 React 前端开发者的循环。

## 我后来想明白一件事：组件库是"菜谱"，不是"成品菜"

你从组件库里真正需要的，从来不是那盘成品菜——而是**菜谱**：

- 下拉框：方向键怎么选、回车怎么确定、Escape 怎么关
- 弹窗：焦点怎么锁、关掉之后焦点还去哪儿、滚动怎么锁
- 无障碍：读屏软件听到什么、ARIA 角色挂在哪个节点上

**这些行为逻辑跟框架无关。** 它只是恰好被用 React 语法写了一遍而已——就像川菜菜谱用中文写，不代表只有会中文的人才能做川菜。

而"成品菜"——颜色、间距、圆角、阴影——本来就该由你自己的设计系统说了算。别人的样式，永远是你的参考，不该是你的全部。

| 菜谱（行为契约） | 灶台（你的框架） | 摆盘（你的样式） |
|---|---|---|
| 状态、键盘、焦点、ARIA | Svelte 5 的 runes / Vue 的 v-model / Solid 的 signal | 设计 token、StyleX、Tailwind |

菜谱不该被厨房锁死。你要做的，只是把菜谱**翻译**成你家灶台的用法。

## recomp 就是这位翻译——一个 AI 帮厨

你递一份菜谱（组件库文档 URL），它还你一份能上你家灶台的菜谱（headless 组件源码）：

- **翻译是"意译"不是"直译"**：React 的受控模式 → Vue 的 `v-model`、Svelte 的 `bind:`、Solid 的 signal + callback，按你家框架的习惯来，不是把 JSX 改个名就交差
- **菜谱缺了步骤？对照规范补全，并告诉你**：文档没写的行为，按 WAI-ARIA 的标准做法（APG 模式）补上，交付时明确标注"这一步是按规范补的"
- **摆盘完全归你**：它只交付"样式接口契约"——data-attribute 全集、class 插槽、CSS 变量，怎么摆是你的设计系统说了算

## 这个帮厨，规矩我事先摊开讲

AI 干活，谁都会问一句"信得过吗"。它的规矩就四条：

1. **看不懂的菜谱，明说，绝不瞎编。** 你递过来的是博客、工具库、设计稿？直接拒单并说明原因。ARIA、焦点、键盘这些"味道"它不猜——要么按规范补，要么明确告诉你这块没做，宁可留白不做假
2. **不进你的厨房乱动。** 探测你的框架、CSS 方案、设计 token 时只读——不建目录、不改文件，探测结果只用在这一单上，用完即弃
3. **你家已会做的菜，不重复做。** Solid 有 Kobalte、Vue 有 Reka UI、Svelte 有 Bits UI——生态里已有等价物，它直接推荐你用现成的，不浪费你的时间
4. **只学做法，不抄成品。** 复刻的是接口和行为，不搬别人的源码和样式值，来源留档，商用也安心

一句话：**它负责把菜谱翻译好，放不放辣椒、摆成什么样，你说了算。**

## 上桌流程，三步

```sh
# 安装：路径里的 /recomp 就是技能名，无需再加 -s
npx skills add brickhu/skills/recomp
```

1. **递菜谱**——发组件库文档 URL（比如 shadcn/ui 的 Dialog 文档）
2. **看菜单**——它先报一份"行为契约摘要"：接口、行为、每一步做法的出处（来自文档 / 按规范补全 / 留给你拍板），你确认再看代码
3. **端走装盘**——源码按文件完整输出在对话里，复制进你的组件目录，接上你的样式，完事

不满意？直接说："Escape 处理不对""这里用 bind 不要用 v-model"——它当场重出完整文件，不用打补丁。
